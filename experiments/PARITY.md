To repeat the frontend round trip, run the following from the repository root, substituting the final native executable and SDK paths. The script exports and instruments a disposable WPF source copy and creates a fresh isolated database.

```powershell
./experiments/tools/Verify-DatabaseCompatibility.ps1 -NativeExecutable <native-exe> -Dotnet <dotnet-exe>
```

For the native desktop enumeration/notification and synthetic hotkey probes, run the executable with `--desktop-probe` and `--hotkey-probe`, respectively. These do not simulate a physical desktop move or key press.

The subsequent interactive native checks and isolated move-probe commands are recorded in [Native interaction checks](NATIVE_INTERACTION_CHECKS_2026-11-12.md). The probe initiates the Windows COM moves; the decision buttons were exercised interactively.

An undecided new Avalonia desktop move records a null destination before any move transaction. The final note/session changes and marker deletion commit together. Unmodified WPF skips migration for a null destination and then deletes the marker, safely cancelling the uncommitted decision; its review prompt does not survive that cross-open. Legacy non-null markers do not identify which target notes moved, so Avalonia retains them for explicit review rather than moving potentially unrelated notes. These behaviors preserve schema version 2.
